# Universal Research Pipeline — Builder's Constitution

> **Read before modifying the Meta-Framework or generating pipelines.**

---

## 1. The One Rule

**Every research prompt must maximize empirical depth and eliminate speculation.**

If a prompt produces generic advice that could apply to any generic web app, the prompt has failed. Every prompt must yield specific tool names, verified version numbers, exact pricing tiers, concrete schemas, and runnable code patterns.

---

## 2. The 8 Core Principles

### P1: The Aspect-Isolation Law
Research topics must be partitioned into dedicated, single-topic sessions. Bundled topics dilute search budgets and degrade analytical depth.

### P2: Nothing Is Sacred
All initial specifications and architectural assumptions are hypotheses. Empirical research overrides all pre-conceived ideas.

### P3: Compose (~40%) + Build (~60%)
Never reinvent solved problems (Auth, DB, Storage, UI Primitives, Job Queues). Build custom only for proprietary algorithms, domain state machines, and specialized workflows.

### P4: Live Temporal Grounding
Mandate current-year searches, verified LTS releases, and deprecation audits. Never recommend abandoned packages.

### P5: Unbiased Landscape First, Filtered Decisions Second
Tier 1 catalogs the universe of options without bias. Tier 2 selects and filters against project-specific constraints.

### P6: Structured Markdown Artifacts
All session responses must be delivered as complete, copy-pasteable Markdown File Artifacts.

### P7: Triangulate & Grade Evidence
For critical decisions, run across multiple frontier models and grade claims from Grade A (Specs/Code) to Grade E (Speculation).

### P8: The Phase 0 Gate
Strict exit criteria must be satisfied before initializing repository scaffolds and writing code.
