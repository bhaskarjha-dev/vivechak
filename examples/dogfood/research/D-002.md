# D-002: Workspace Storage Model: Confined File-Based Store vs SQLite

## Context & Problem Statement

Vivechak persists research artifacts (`RESEARCH-PIPELINE.md`, `DECISIONS.md`, `FAD.md`, and individual session/comparison files)
across multiple interactive sessions and subagents. The persistence engine must satisfy several critical architectural requirements:
1. **Zero External Dependencies / CGO-Free:** Single static binary distribution (`CGO_ENABLED=0`) across 7 OS/architecture targets.
2. **Human Readability & Git Friendliness:** Research artifacts must be standard Markdown files committed to the user's version control repository.
3. **Confinement & Security:** Mitigate directory traversal and unauthorized path escapes outside the designated `research/` directory.

## Evaluated Options

1. **Option A: SQLite Database (`database/sql` + modernc.org/sqlite or mattn/go-sqlite3)**
   - *Pros:* Atomic ACID transactions, robust SQL queries, built-in concurrency controls.
   - *Cons:* Binary database file is opaque in git diffs; `mattn/go-sqlite3` requires CGO toolchains for cross-compilation; pure Go SQLite adds ~3 MB to binary size and obscures plain Markdown deliverables (Grade B · empirical evaluation | cached).
2. **Option B: Confined File-Based Store (`internal/store`)**
   - Files stored directly on filesystem as standard UTF-8 Markdown and JSON files.
   - Path confinement via Go 1.24+ `os.Root` abstraction (and fallback sanitizer) preventing path escapes.
   - Concurrency managed via atomic temporary file replacement (`store.WriteFileAtomic`) and advisory file locks (`research/.locks/`).
   - Revision history maintained in `research/.history/` for conflict tracking and recovery.
   - Evidence: Zero CGO required, cross-compiles cleanly on all platforms, 100% human-readable git diffs in pull requests (Grade A · source inspection | verified).

## Decision Outcome

**Chosen Option:** Option B — Confined File-Based Store (`internal/store`).

### Rationale

- **CGO-Free Cross-Compilation:** Compiles cleanly to standalone static binaries on macOS (Intel/ARM), Linux (x86_64, ARM, ARM64), and Windows.
- **Git Native Ergonomics:** Architectural decisions and research pipelines are first-class version-controlled Markdown artifacts that human engineers can review in PRs.
- **Safety Guarantee:** Confinement via `os.Root` ensures no MCP command or malicious path parameter can escape the `research/` directory.

## Rejected Alternatives & Tradeoffs

- **Rejecting SQLite (Option A):** SQLite would make research artifacts opaque to developers reading GitHub repositories. Storing markdown inside a database requires additional dump/export steps, violating Vivechak's dual-audience principle (P6).
- **Rejecting unconfined direct I/O:** Bare `os.WriteFile` without atomic rename or `os.Root` confinement is vulnerable to symlink traversal and partial write corruption during sudden agent process crashes.

## Failure Modes & Reversal Triggers

- **Failure Mode 1:** High write contention between parallel subagents causing file lock timeouts.
  - *Mitigation:* Advisory locks use short backoff intervals with non-blocking try-lock semantics, returning clear `E-LOCKED` guidance.
- **Reversal Trigger:** If multi-agent research workloads with >10 concurrent subagents experience lock contention latency exceeding 500ms, evaluate introducing an embedded pure-Go transactional engine for intermediate index state.
