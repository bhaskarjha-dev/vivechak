## 1. Executive Philosophy & The First-Principles Law

> **The Research-First Law:**  
> *"Before beginning any development, execute comprehensive, live, multi-dimensional research on every aspect, landscape, and decision. Develop nothing based on cached assumptions, outdated training data, or hallucinated conclusions."*

Software failures, architectural rewrites, and wasted engineering cycles are almost never caused by poor coding — they are caused by **premature decisions made on unverified assumptions**.

The Universal Research Pipeline is an autonomous, structured pre-development engine designed to discover, evaluate, resolve, and synthesize the total technical and strategic foundation of any software venture *before a single line of application code is written*.

## 2. The 8 Non-Negotiable Axioms

### Axiom 1: Nothing Is Sacred
Every document, specification, stack preference, and schema drafted prior to research completion is strictly a **HYPOTHESIS**, not a decision. If empirical research produces evidence contradicting initial assumptions, the assumptions die, not the research.

### Axiom 2: Compose First, Build Custom for Differentiated Value
A solo engineer or lean team cannot out-build multi-billion dollar ecosystems on solved infrastructure.
- **~40% Composed Infrastructure:** Auth, Database, Storage, Real-time Sync, Base UI Components, Email/Notification Gateways, Logging, Rate Limiting.
- **~60% Custom Domain Logic:** Proprietary evaluation algorithms, domain state machines, unique workflows, specialized compliance/cultural logic.

### Axiom 3: Temporal Grounding & Live Verification
AI models suffer from stale knowledge. Every research session enforces:
- Explicit search instructions for the current year/date.
- Pinned version numbers, release dates, and LTS status.
- Verification of pricing models, open-source license changes, and community health metrics.
- Hard ban on recommending deprecated, discontinued, or abandoned packages.

### Axiom 4: Unbiased Discovery Precedes Filtered Selection
Never jump straight into comparing your favorite 2 tools.
- **Tier 1 MUST be unbiased:** Catalog every tool, platform, competitor, and approach that exists globally.
- **Tier 2 selects and filters:** Compares candidate architectures against project-specific constraints.

### Axiom 5: Complete Markdown Artifact Output Contract
Research outputs must never be conversational summaries. Every session prompt strictly mandates a self-contained, structured **Markdown File Artifact** formatted with clear headers, comparison tables, code snippets, decision sections, and inventory matrices.

### Axiom 6: Traceability & The Decision Registry (D-NNN)
Every architectural choice must be assigned a permanent identifier (`D-001`, `D-002`, etc.) documenting:
1. Context & problem statement
2. Options considered with pros/cons
3. The chosen option and exact rationale
4. Rejected alternatives and why they were discarded
5. Evidence source (which research session produced the data)

### Axiom 7: The Triangulation & Verification Standard (from Triyantra)
For mission-critical strategic foundations:
- **Multi-Model Triangulation:** Run identical prompts across frontier models (Claude, ChatGPT Deep Research, Gemini) to eliminate single-model bias.
- **Evidence Grading (Grade A–E):**
  - **Grade A:** Primary documentation, official specs, live RFCs, verified source code.
  - **Grade B:** Reputable third-party empirical benchmarks, engineering postmortems.
  - **Grade C:** Official vendor marketing claims.
  - **Grade D:** General blog posts / unverified tutorials.
  - **Grade E:** Unsupported AI speculation / unverified stats.

### Axiom 8: The Phase 0 Gate
No application repository is scaffolded or coded until `SYN-01` produces the **Founding Architecture Document (FAD)** and all items in the Phase 0 checklist are resolved.

## 3. The 6-Phase Research-to-Roadmap Methodology

Derived from the Triyantra, Vivah, and Portfolio research engines:

```
1. EXTRACT    ==>  2. VERIFY     ==>  3. CONSOLIDATE
(Raw outputs)      (Grade A-E)        (Topic KB)
                                           ||
6. VALIDATE   <==  5. SYNTHESIZE <==  4. CHALLENGE
(Day 1 test)       (Ground-up)        (Inversion)
```

1. **Phase 1: EXTRACT — Complete Capture:** Run all Tier 1–3 sessions without interruption, capturing raw outputs.
2. **Phase 2: VERIFY — Separate Fact from Speculation:** Grade all claims (A–E), source-check statistics, verify that recommended repos are actively maintained.
3. **Phase 3: CONSOLIDATE — Topic Knowledge Base:** Build "What We Know For Sure" — 2-3 pages of pure Grade A/B facts.
4. **Phase 4: CHALLENGE — Stress Test Everything:**
   - *Inversion Test:* For each core conclusion, write the opposite claim and test if it holds.
   - *"What If We're Wrong?":* Identify 3-5 load-bearing assumptions and define what would falsify them.
   - *Devil's Advocate:* Argue the case of a skeptical user, competitor, and architect.
5. **Phase 5: SYNTHESIZE — Ground-Truth Up Roadmaps:** Build from ground truth facts UP to problems, then to features, then to build order. (Never vision-down rationalization).
6. **Phase 6: VALIDATE — Reality Check:** Day 1 User Walkthrough, Phase 1 Completeness Test, Task-level implementation readiness.

## 4. The 3-Tier Staging Model

### Tier 1: Problem & Landscape (Unbiased Discovery)
- **Objective:** Map the entire problem space and ecosystem without bias.
- **Execution Mode:** 100% Parallel. Sessions run independently.
- **Standard Sessions (4–8 sessions):**
  1. *Ecosystem & Competitor Landscape* (Direct, indirect, and adjacent tools)
  2. *Domain Operations & Real-World Workflows* (How humans/businesses currently do it manually)
  3. *User Behavior, Psychology, & Pain Points* (Decision dynamics, cognitive biases)
  4. *Regulatory, Privacy, Legal, & Security Standards* (Data protection, compliance requirements)
  5. *Market Size, Distribution, & Monetization Dynamics* (Pricing models, CAC, adoption channels)

### Tier 2: Solution & Architecture (Decision-Focused)
- **Objective:** Evaluate competing technical paradigms and make binding architectural decisions.
- **Execution Mode:** Parallel for independent domains, sequential for dependent stacks.
- **Standard Sessions (8–12 sessions):**
  1. *Frontend Architecture & Framework Selection* (Next.js, Remix, SvelteKit, Vite)
  2. *Backend Runtime, API Protocol & Framework* (Fastify, Hono, NestJS, Go, Rust / REST, GraphQL, tRPC)
  3. *Database Engine, Multi-Tenancy & Schema Design* (PostgreSQL, Neon, Supabase, ClickHouse / RLS, Partitioning)
  4. *Authentication, RBAC & Multi-Tenant Identity* (Better Auth, Clerk, Lucia, Auth.js)
  5. *UI Design System, Component Library & Styling* (shadcn/ui, Tailwind v4, Radix primitives)
  6. *Real-Time Communication & Collaboration Engine* (Socket.IO, WebSockets, SSE)
  7. *Document Vault, File Storage & Field Encryption* (Cloudflare R2, S3, AES-256-GCM)
  8. *Deployment, Cloud Infrastructure & CI/CD* (Dokploy, Coolify, Cloudflare Workers, AWS, Docker)
  9. *Internationalization (i18n), Localization & Typography* (Multi-language, font subsets)
  10. *Platform Strategy: Build from Primitives vs Extend Platform* (Custom vs Headless/Open-Core)

### Tier 3: Implementation Blueprints (Build-Ready)
- **Objective:** Generate production-ready schemas, algorithms, state machines, and API contracts.
- **Execution Mode:** Strictly Sequential (each blueprint builds upon the preceding data model).
- **Standard Sessions (4–8 sessions):**
  1. *Data Model, Entity Architecture & Drizzle/Prisma Schema*
  2. *Core Domain Algorithm & Mathematical Engines* (Pure functions, zero DB dependencies)
  3. *Domain Workflow, Pipeline State Machine & Transition Matrix* (XState/Custom state machine)
  4. *Subsystem Integration & External Service Bridges*
  5. *Mobile-First Responsive Architecture, Performance Budgets & Touch Patterns*

### Synthesis: Grand Integration (SYN-01)
- **Objective:** Ingest all T1, T2, and T3 outputs, detect and resolve inter-session conflicts, run inversion tests, and output the **Founding Architecture Document (FAD)**.

## 6. Conflict Resolution Protocol (The CHK Engine)

When parallel research sessions make conflicting recommendations (e.g., T2-02 recommends Node.js while T2-08 benchmarks Go for raw latency), execute a dedicated Checkpoint Session (`CHK-01`):

1. **Collate Conflict Pairs:** Extract the exact opposing claims and data points.
2. **First-Principles Evaluation Matrix:** Evaluate against the project's non-negotiable constraints.
3. **Formal Resolution Verdict:** Choose the winning path, document why the alternative was rejected, and update `FINAL-STACK.md` and `DECISIONS.md`.

Before creating the git repository or writing code, verify all 9 items:

- [ ] All Tier 1 discovery sessions completed and saved as markdown artifacts.
- [ ] All Tier 2 architectural decisions completed with clear winners and rejected options.
- [ ] All Tier 3 implementation blueprints generated with copy-pasteable schemas and algorithms.
- [ ] `SYN-01` Grand Synthesis completed → `Founding Architecture Document (FAD)` produced.
- [ ] Inversion stress tests passed and recorded in Challenge Register.
- [ ] All conflicts resolved via `CHK` checkpoints.
- [ ] `DECISIONS.md` initialized with all `D-001...` entries marked `RESOLVED`.
- [ ] `ARCHITECTURE.md` updated with pinned versions and zero "TBD" items.
- [ ] Project scaffold initialized strictly as per the FAD stack.
- [ ] First commit created: `feat: initial project scaffold based on Founding Architecture Document`.
