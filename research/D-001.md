# D-001: Consolidate MCP Tool Surface from 13 to 9 Tools

## Context & Problem Statement

Prior to v0.1.0, Vivechak exposed 13 distinct Model Context Protocol (MCP) tools:
`vivechak_init`, `vivechak_prepare_generator`, `vivechak_save_plan`, `vivechak_status`, `vivechak_next_session`,
`vivechak_save_session`, `vivechak_record_decision`, `vivechak_amend_session`, `vivechak_validate`, `vivechak_run_gate`,
`vivechak_challenge`, `vivechak_replan`, and `vivechak_visualize`.

In multi-harness autonomous testing across diverse client hosts (Claude Code, Cursor, OpenCode, Antigravity, Factory Droid),
we observed cognitive friction in smaller models (e.g. Nemotron, GLM, GPT-4o-mini). Models frequently confused `save_plan`
vs `save_session`, or called `init` unnecessarily before `prepare_generator`. The total tool schema payload exceeded 18 KB,
consuming a disproportionate percentage of agent system prompt context.

Quantitative constraint: The complete tool definition payload should remain under 10 KB to preserve agent context budget.

## Evaluated Options

1. **Option A: Retain 13 Fine-Grained Tools with Disambiguation Prompts**
   - Evidence: Multi-harness empirical runs showed a 22% failure rate where agents called `vivechak_save_plan` when saving session outputs, or stalled trying to decide between `init` and `prepare_generator` (Grade B · empirical · direct | cached).
2. **Option B: Consolidate to 9 High-Cohesion MCP Tools**
   - Combine initialization and prompt retrieval into `vivechak_start(scope, question)`.
   - Combine plan, session, comparison, and FAD persistence into polymorphic `vivechak_save(kind, id, content)`.
   - Combine validation and coaching observations into `vivechak_review(session_id, content)`.
   - Rename `next_session` → `vivechak_next`, `run_gate` → `vivechak_gate`, `amend_session` → `vivechak_amend`.
   - Evidence: Consolidates total tool schema footprint from 18 KB down to 8.4 KB (53% context reduction), eliminates initiation ceremony, and unifies save persistence under a single predictable contract (Grade A · source inspection | verified).

## Decision Outcome

**Chosen Option:** Option B — Consolidate the tool surface from 13 to 9 cohesive MCP tools (`vivechak_start`, `vivechak_save`, `vivechak_record_decision`, `vivechak_next`, `vivechak_status`, `vivechak_review`, `vivechak_amend`, `vivechak_replan`, `vivechak_gate`).

### Rationale

- **Guided Worker Protocol:** Every response envelope includes a structured `next` field (`tool`, `args`, `why`), removing guesswork for agents.
- **Zero-Ceremony Auto-Initialization:** `vivechak_start` and `vivechak_save` transparently initialize the workspace on the fly if `.vivechak.json` does not exist, eliminating dead `init` turns.
- **Context Preservation:** Total schema footprint is reduced by >50%, strictly satisfying the ≤10 KB budget requirement.

## Rejected Alternatives & Tradeoffs

- **Rejecting Option A (13 tools):** Maintaining 13 granular tools increased maintenance overhead and caused model navigation failures in smaller parameter models without providing additional epistemic grounding capability.
- **Rejecting extreme consolidation (3 tools):** Consolidating everything into 3 mega-tools (`vivechak_query`, `vivechak_mutate`, `vivechak_admin`) would hide parameters behind complex sub-schemas, degrading discoverability in tool-calling LLMs.

## Failure Modes & Reversal Triggers

- **Failure Mode 1:** Host agent fails to specify `kind` in `vivechak_save`.
  - *Mitigation:* The tool validates `kind` against recognized enum values (`comparison`, `plan`, `session`, `fad`) and returns explicit helpful error guidance with valid options.
- **Reversal Trigger:** If future benchmarks across ≥3 major agent hosts demonstrate that separate `save_plan` and `save_session` tools outperform polymorphic `vivechak_save`, re-open this decision via D-03.
